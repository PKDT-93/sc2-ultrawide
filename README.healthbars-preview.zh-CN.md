# 国服 98370 血条比例修复预览版

这是包含原有超宽/HUD 功能以及可单独启停的状态条比例修复的预览版。自带 Python 与 Tk，运行不需要安装 Python、Capstone 或 PyInstaller。PyInstaller 只用于构建。

**已知问题：运输单位的装载格仍有比例问题，例如折跃棱镜血条下面的载客格子。本版未修复装载格，不代表全部头顶 UI 都已适配。**

适用条件：Windows x64，国服加载 build 98370，窗口化全屏，3440×1440，单人战役。游戏 EXE 的文件版本可能显示 5.0.15.98370；使用加载 build 作为校验依据。

## 如何用

1. 通过国服 Battle.net 打开游戏，保持窗口化全屏。
2. 双击 `SC2-Ultrawide-Healthbars-Preview.exe`。打开窗口本身不会访问游戏内存。
3. 根据需要点击“启用超宽 + 自动修复 HUD”。
4. 进入战役，让单位状态条可见，点击“启用血条比例修复（实验）”。
5. 保持工具窗口打开；血条修复会跟随本次游戏进程和任务切换。

“停止血条修复”只撤回状态条回调。关闭工具窗口会先停止并恢复血条修复；原有 HUD 助手仍按原有机制运行到游戏退出。若要恢复 16:9，先停止血条修复，再点“恢复 16:9”。每次重启游戏后需要重新启用。

状态条修复使用独立开关，不会随原有“启用超宽”按钮自动启用。重复打开窗口时，进程互斥锁阻止重复接入。

## 本次修复做什么

每条已识别的分段状态条围绕自身中心，将最终顶点横坐标乘以 2560/3440，即约 74.42%；格子、左右黑边和间距同步压缩。纵坐标、颜色、纹理坐标和分段数量保持不变。

覆盖已校验的普通分段条及双排组合状态条路径，并接入同一绘制路径中的独立资源条。一次取样的样本数不是处理上限；实际按每帧绘制列表处理。界面统计的是处理的“状态组”数量，一组可能有两排，不是整关的单位总数。

## 验证与限制

已在本机验证雷诺、陆战队员，以及换关后的跳虫、蟑螂、刺蛇、脊针爬虫等对象；捕获到普通兵约 100%、60%、33%、6.7% 血量及对应颜色变化。用户已确认雷诺的格数、边框、间距和位置正常，并确认图形按钮“启停正常，组合条也自然”。组合状态条的绘制数据与恢复操作也已在真实进程验证。

目前支持普通分段条 1–63 格、双排组合条 1–31 格，以及每帧最多 4096 个候选对象。超出边界、未分段状态条及不匹配的绘制路径会跳过。这些是安全边界，并非所有游戏内容均已验证。其他 build、分辨率、渲染器和全部战役场景未验证。真实退出游戏的生命周期用模拟测试覆盖，未在本轮强制关闭用户游戏。

## 机制和风险

这项功能会把原生绘制回调写入新分配的游戏进程内存，并临时替换对象的可写虚表指针；新分配代码页由 RW 转为 RX。游戏原有代码页、EXE、配置、存档和 Battle.net 文件均不改写。不申请管理员权限，不创建服务或开机启动，不尝试绕过反作弊。

它比原有 HUD 参数修改更深入，仍有崩溃及账号风险，不能视作账号安全保证。仅用于自行承担风险的单人战役测试。

窗口关闭或停止按钮会禁用回调并恢复当前指针。控制器异常终止时，原生回调的渲染帧心跳租约到期后会自行禁用并恢复顶点池指针；这不是即时退出保证。为避免在途调用引用已释放代码，每次启用后保留 64 KiB 禁用分配，游戏退出时由系统回收。图形设备/缓冲区更换或窗口分辨率变化时停止，需手动重新启用。

日志位于 EXE 同目录的 `logs/healthbars.log`。不上传日志或游戏数据。

## 构建与检查

```
.venv-build\Scripts\python.exe -m unittest test_healthbar_native test_healthbars test_compatibility -v
.\build-portable.ps1 -HealthbarsPreview
```

28 项测试包括 `test_healthbar_native.py` 中的隔离原生算法、映射参数、组合条、容量边界和租约失效测试。这些原生测试只在独立测试子进程分配内存，不打开游戏。机制与调用约定见 [原生回调审阅说明](NATIVE_HEALTHBARS.md)。

构建后的 EXE 另有显式、限时的打包运行时检查入口 `--health-test-seconds 15`。该检查会实际修改游戏内存，普通用户使用图形按钮即可。
